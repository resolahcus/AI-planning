## 擷取方法與完整檢查

1. 使用 `pdfplumber` 依表格列擷取，區分答案欄、題號欄與題目內容。移除頁首、頁尾、表頭與題號，但保留完整題幹、所有選項文字及原文標點。
2. 遇到沒有新題號的下一頁首列，將該列接回上一題，並記錄兩頁來源。共續接 60 列；沒有把跨頁片段誤當成新題。
3. 六份檔案均驗證題號完整且依序為 1–50；全題庫共 300 個唯一 ID。
4. 全部 300 題均驗證選項標記依序為 A、B、C、D，題幹與四個選項皆非空白。原始答案均為 A–D，無複選、缺答或特殊給分。
5. 另外使用 PDF 座標欄位重新讀取全部題號與答案，與表格擷取結果逐筆比對，300 題均一致。
6. 每一個題目／續接列均以 PDF 文字物件做非空白字元覆蓋檢查；共 360 列通過，未遺漏或多出非空白字元。將拆出的題幹與選項重新組合後，也與原擷取文字逐字比較（僅忽略空白），300 題全部相同。
7. 使用另一個 PDF 讀取器 `pypdf` 獨立確認六份頁數，並確認每份 PDF 的 `(A)`、`(B)`、`(C)`、`(D)` 標記各出現 50 次。
8. 確認無 Unicode replacement character 或 NUL，且題目內容沒有混入已辨識的頁首及頁尾。

只正規化 PDF 排版換行：中文跨行接續，英文單字間保留空格，英文字尾連字號保留。原檔的措辭、可能的筆誤或答案均不自行改寫。

## 解答與解析的界線

`answer` 是原 PDF 公告答案的抄錄；驗證證明題庫與原始檔案對應一致，不代表另外完成每題學理正確性的審查。

六份原檔均無逐題詳解，因此全部 `explanation` 保留 `null`。網站應顯示「原公告未提供解析」或等義說明，不可將生成內容標示為官方解析。後續若加入人工或 AI 輔助解析，應另存其來源、覆核狀態與版本。

## 重跑方式

交付包中的 `scripts/extract-questions.py` 可從隨附 `sources/` 的六份短檔名 PDF 重建題庫，完全不依賴原電腦的下載資料夾。需要 Python 3.10 以上；擷取專用套件版本記錄於 `scripts/requirements-extract.txt`。網站啟動、建置及使用既有題庫都不需要 Python。

在專案根目錄執行：

```powershell
python -m pip install -r scripts/requirements-extract.txt
python scripts/extract-questions.py
```

預設來源與輸出位置依腳本所在的專案目錄解析，分別為 `sources/`、`data/`。可使用 `--source-dir` 指定另一個來源資料夾，支援六份原始中文檔名或隨附的短檔名；使用 `--output-dir` 指定 JSON 輸出資料夾，或使用 `--report` 指定機器可讀驗證摘要的檔案路徑。

```powershell
python scripts/extract-questions.py --source-dir ./sources --output-dir ./work/rebuilt-data --report ./work/extraction-checks.json
```

腳本先驗證六份來源的固定 SHA-256，再完成全部擷取及檢查才寫入 JSON；任何來源版本、題號、答案、選項或字元覆蓋檢查不一致會以錯誤中止。重新擷取不會產生詳解或修改原始 PDF。此腳本專為這六份版型及版本建立，新增其他年度或改版試題需另行驗證。
